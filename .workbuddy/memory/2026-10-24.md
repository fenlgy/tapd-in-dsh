## 0.3.1：需求正文按富文本渲染（commit d3421a2）

- 用户反馈：「需求描述中是 html 的源码，需要看到的是渲染后的效果」。
- 实证：TAPD `description` 是 TinyMCE 产物，形如
  `<div><b>需求描述：</b></div><div><p>…</p></div><p class="tox-clear-float"><img src="/tfl/captures/…" width="80%"></p>`。
- **关键坑（实测）**：`www.tapd.cn/tfl/...` 匿名访问 302 到 `cloud_logins/login`，Bearer 令牌也不管用；
  正确姿势是 Open API `GET /files/get_image?workspace_id=&image_path=` 换签名地址
  （`file.tapd.cn/attachments/tmp_download/…`，300 秒有效）。**该地址回的 `Content-Type` 是残缺的 `image`（无子类型）**，
  必须按后缀补成 `image/png`，否则浏览器不一定肯解码。
- 宿主侧：`src/tapd.ts` 加 `getImageUrl()`；`src/routes.ts` 加 `GET /tapd/__image?path=`，
  用 `Readable.fromWeb(上游.body).pipe(res)` **转发字节**（不用 302：页面在 `dsh-app://app` 自定义协议上，
  少一层跳转少一处不确定）。路径做白名单 `^/[A-Za-z0-9._~/-]+\.(png|jpe?g|gif|bmp|webp)$` 且禁 `..`。
  取不到时回一张 SVG 占位图（`图片加载失败`），不是错误页。
- 浏览器侧：`client.js` 加 `#region 富文本`——`sanitizeRichText()` 用 DOMParser 解析后递归清洗：
  - 标签白名单（p/div/span/b/strong/…/table/img/a/font…），`script/style/iframe/form/svg/…` 连内容丢掉，
    不认识的标签 **unwrap**（留文字丢标签，避免整段消失）；
  - 属性按标签放行（a: href/title，img: src/alt/width/height…），`style` 只留排版类声明且拒 `url()/expression`；
  - `href` 只放行 http(s) 与 `#`（`javascript:` 直接摘掉，实测断言过）；`src` 里 `/tfl/`、`/tapd3/` 改写成 `/tapd/__image?path=`；
  - 空白块 `<div><br></div>` 打 `data-blank` 且 margin 归零，否则连续空行把正文撑出比 TAPD 大一倍的空白。
  - 图片 `error` 事件（innerHTML 里的元素挂不上 React 事件）→ 挂载后补监听，替换成「图片加载失败」提示；
    用 `img.complete && naturalWidth === 0` 补一刀缓存命中失败的情况（jsdom 下 complete=false，不会误伤）。
- 顺手：`renderStoryContext` 注入给模型的正文改 `htmlToText()`（图片折 `[图片]`），列表 `summarize()` 也不再漏标签。
  新增 `src/richtext.ts`（无 DOM 的 HTML→文本）。
- 测试：新增 `test/panel.smoke.mjs`（jsdom + 真 React 18 挂载，22 条断言，含 XSS 载荷：
  script/style/onerror/onclick/javascript:/position）。为此加 devDeps `jsdom@30 react@18.3.1 react-dom@18.3.1`。
  `test/routes.smoke.mjs` 的假 res 改成真 `Writable`（图片是流式转发的），新增 6 条图片断言。
- 实证脚本（可复用）：`/tmp/tapd-route-image.mjs` 用真实配置跑一遍路由拿到 342962 字节 PNG；
  `/tmp/tapd-preview/render-rich.mjs` 拿真实需求正文渲染详情页并用 playwright 截图（`v4-detail.png`）。
  注意该脚本的 `locale.bind` 必须查字典，否则界面全是 key 字面量。
- 仍待用户确认：行内「插入」图标半透明是否需要常驻；`@tapd:story` 的「在 TAPD 打开」仍走 `<a target=_blank>`。
