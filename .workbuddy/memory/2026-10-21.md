## DSH 安装方式（实机核实）
- 本机 DSH = 桌面版 `/Applications/DeepSeek Harness.app`，跑的是 `~/.dsh/profiles/desktop`（非 web profile）。
- `dsh` 命令默认**不在 PATH**；CLI 实体在 `.../Contents/Resources/runtime/cli/bin/dsh`，
  桌面端会用提权方式软链到 `/usr/local/bin/dsh`（command-manager.js），本机尚未安装。
- 插件管理机制（读 dsh bin.js / plugin-BiveYA7h.js / plugin-manager README 确认）：
  - `dsh plugin --profile <p> <pnpm 参数>` 直接透传 pnpm，先写入 profile 依赖再选为组合包。
  - `--profile desktop` 必须先**完全退出桌面端**（requireDesktopProfile 会检查 profile 是否已初始化）。
  - 插件的 `cordis.patch.yml` 就是「组合包 patch」，格式与官方 auto-review 一致（`- insert: - id/name`）。
  - 图形界面路径：侧栏「插件」→ 添加插件 → 支持包名 / Git 地址 / 压缩包 / 本地绝对路径。
  - 版本兼容按 `engines.dsh` 或 DSH peer 包校验，不满足需 `dsh plugin allow-version ... --accept-risk`。
  - git 安装靠 `prepare` 脚本构建，pnpm 默认拦构建脚本，需写 `allowBuilds` 到 profile 的 pnpm-workspace.yaml。
