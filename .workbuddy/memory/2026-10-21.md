## DSH 安装方式（实机核实）
- 本机 DSH = 桌面版 `/Applications/DeepSeek Harness.app`，跑的是 `~/.dsh/profiles/desktop`（非 web profile）。
- `dsh` 命令默认**不在 PATH**；CLI 实体在 `.../Contents/Resources/runtime/cli/bin/dsh`，
  桌面端会用提权方式软链到 `/usr/local/bin/dsh`（command-manager.js），本机尚未安装。
- 插件管理机制（读 dsh bin.js / plugin-BiveYA7h.js / plugin-manager README 确认）：
  - `dsh plugin --profile <p> <pnpm 参数>` 直接透传 pnpm，先写入 profile 依赖再选为组合包。
  - `--profile desktop` 必须先**完全退出桌面端**（requireDesktopProfile 会检查 profile 是否已初始化）。
  - 插件的 `cordis.patch.yml` 就是「组合包 patch」，格式与官方 auto-review 一致（`- insert: - id/name`）。
  - 图形界面路径：侧栏「插件」→ 添加插件 → 支持包名 / Git 地址 / 压缩包 / 本地绝对路径。
  - 版本兼容按 `engines.dsh` 或 DSH peer 包校验，不满足需 `dsh plugin allow-version ... --accept-risk`。
  - git 安装靠 `prepare` 脚本构建，pnpm 默认拦构建脚本，需写 `allowBuilds` 到 profile 的 pnpm-workspace.yaml。
- 关键发现：`lib/` 被 gitignore，原 package.json 无 `prepare` → 从 GitHub 装会是空壳。已补 `"prepare": "npm run build"`。
- README 安装章节按上述事实重写；提交 2c10837 已推送。
- 运行时版本：node 24.21.0 / pnpm 11.28.5（runtime/versions.json）。

## 0.2.1：修 pnpm 拒绝构建脚本（`ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED`）
- 现象：在 DSH 客户端填 Git 地址安装，pnpm 11.28.5 报
  `The git-hosted package "tapd-in-dsh@0.2.0" needs to execute build scripts but is not in the "allowBuilds" allowlist`。
- 根因：0.2.0 为了从 GitHub 装能用，加了 `"prepare": "npm run build"`，而 `lib/` 在 .gitignore 里。
  pnpm 对 git 依赖的生命周期脚本默认拦截（供应链策略），且 allowBuilds 的 key 带 commit URL，每换个 commit 就要重配，客户侧体验不可接受。
- 修法（放弃 allowBuilds 路线，改为「客户侧零脚本」）：
  - `lib/`（20 个文件、124K）从 .gitignore 移除并提交入库；
  - 删除 `prepare`，仅保留 `prepublishOnly`（npm 发布前构建）；
  - 版本 0.2.1，提交 72e7d7f 已推送。
- 验证：下载 72e7d7f 的 codeload tarball 解包确认 lib/ 齐全、scripts 无 prepare、main=lib/index.js 存在、client.js 存在。
  再用 runtime 自带 pnpm 11.28.5 在临时 profile 实装：`PREPARE_NOT_ALLOWED` 已消失（推进到解包/hardlink 阶段）。
- 产物依赖面（grep lib/*.js 的 from 子句）：仅 `@deepseek-ai/dsh-llm`、`dsh-tools`、`schemastery`（均为 peerDependencies，由 DSH 运行时提供）+ node 内置模块；client.js 仅 require('react')。
- 注意：本机 devDeps 不全（缺 `@deepseek-ai/dsh-timeout`，是 dsh-llm 的间接依赖），本地 `import('./lib/index.js')` 会 ERR_MODULE_NOT_FOUND，属本地环境问题，不影响客户安装。
- 结论：以后改源码必须 `npm run build` 并**把 lib/ 一起提交**，否则客户装到的是旧产物。
